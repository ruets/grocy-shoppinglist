# Delivery 4 — Internationalisation (FR + EN) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** every UI string comes from a French or English message file, chosen from the phone language (French fallback); numbers and prices follow the language.

**Architecture:** no i18n library. `src/i18n/fr.ts` is the source (nested namespaces, strings or functions for values with parameters); `src/i18n/en.ts` is typed `Messages = typeof fr`, so TypeScript rejects a missing or extra key. `src/i18n/index.ts` picks the language once at startup from `expo-localization`'s `getLocales()` and exposes `t()` (current messages), `lang()` and `locale()` (BCP-47 tag for `Intl` and `localeCompare`). Logic modules that produce text (checkup, grouping, store errors) call `t()` too.

**Tech Stack:** Expo SDK 58, `expo-localization` (in Expo Go), TypeScript, Jest.

**Spec:** `docs/superpowers/specs/2026-11-26-shared-cart-local-products-design.md` (section 7).

## Global Constraints
- Phone language: first preferred locale whose language is `fr` or `en`; none → French.
- Read once at startup (iOS restarts the app on language change).
- Grocy userfield captions (« Prix payé (app) », « DLC (app) », « Rayon (app) ») and the default list name stay French whatever the language — they are stored in Grocy.
- Decimal separator: « , » in French, « . » in English; input accepts both.
- Prices: `Intl.NumberFormat(locale(), currency)`.
- Dates: input and display keep `DD/MM/YYYY` and the existing shortcuts in both languages (the field text is re-parsed, so a single order avoids 03/12 ambiguity); « jamais » / « never » both accepted, shown in the current language.
- Code, comments, tests, commits English.

## Review Focus
- English phone with a region (en-GB, en-US) → English, prices in that region's format (Task 1 test of `pickLanguage` / `localeFor`).
- Phone set to another language first (e.g. de, then en) → English (Task 1 test).
- A string left hard-coded in French → grep check in Task 3 (no French UI literals outside `src/i18n/fr.ts` and the fixed Grocy captions).
- Typing « 1.5 » on a French phone or « 1,5 » on an English one → 1.5 (Task 2 test).
- Tests stay deterministic: Jest setup forces French; English cases set it explicitly.
